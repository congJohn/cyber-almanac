# 规则说明

这份文档解释两件事：**历法部分怎么算的**（可核对），**宜忌部分怎么推的**（本工具的设计）。

---

## 一、历法部分

### 农历

用 1900–2100 年的农历数据表（`LUNAR_INFO`），表里每年一个整数，编码了该年的大小月和闰月信息。基准日是 1900-01-31，即农历 1900 年正月初一。

回归测试覆盖：

| 日期 | 应当 | 说明 |
| --- | --- | --- |
| 2000-01-01 | 戊午日 | 干支基准点 |
| 2023-01-22 | 正月初一 | 春节 |
| 2024-02-10 | 正月初一 | 春节 |
| 2025-01-29 | 正月初一 | 春节 |
| 2026-02-17 | 正月初一 | 春节 |
| 2023-03-22 | 闰二月初一 | 闰月边界 |
| 2026-09-25 | 八月十五 | 中秋 |

跑 `python3 tests/test_calendar.py` 可以自己验一遍。

### 干支

**日柱**用儒略日推算：`序号 = (JDN + 49) mod 60`，0 号为甲子。这个公式在 2000-01-01 上返回戊午，与通行历法一致。

**年柱**用 `(农历年 - 4) mod 60`。

**月柱**用五虎遁："甲己之年丙作首，乙庚之岁戊为头"。即正月天干 = `(年干 mod 5) × 2 + 2`。

**时柱**用五鼠遁：时干 = `(日干 × 2 + 时支序) mod 10`。

### 十二建星

建除十二神：建、除、满、平、定、执、破、危、成、收、开、闭。计算方法：

```
建除序号 = (日支序 - 月建支序 + 12) mod 12
```

### 简化之处（必须知道）

- **月建按农历月定，不是按节气定。** 严格的老黄历里，月建在节气当天才换（立春换寅月，惊蛰换卯月……）。本工具用农历月近似，所以在**节气前后几天**，建除十二神可能和通书差一位。要精确就得引入节气天文算法，那是另一个量级的工程。这个取舍是有意的，也写在了这里。
- **年柱以农历正月初一为界**，不是立春。同理，立春前后几天的年柱可能和严格排盘不同。
- **纳音**按六十甲子的固定表取，无近似。
- **冲煞方位**按三合局取：申子辰日煞南，寅午戌日煞北，亥卯未日煞西，巳酉丑日煞东。

## 二、宜忌部分

### 设计原则

宜忌不是随机抽的，也不是写死的。**每条都由一个可验证的条件触发**，并且必须带理由。

一条规则的形状：

```python
("条件", 返回 宜列表 和 忌列表)   # 每个条目 = (事项, 理由, 权重)
```

条件拿到的上下文包括：

| 维度 | 含义 | 举例 |
| --- | --- | --- |
| `wd` | 星期几 | 周五触发"忌上线" |
| `dd` | 几号 | 1 号触发"宜立 flag" |
| `days_left` | 距月末几天 | 最后一天触发"退订" |
| `jianchu` | 十二建星 | 破日触发"忌动生产环境" |
| `day_ganzhi` | 日柱 | 日干己触发彭祖百忌"不签合同" |
| `day_zhi_i` | 日支 | 子午日触发"忌硬扛" |
| `lunar` | 农历月日 | 初一十五、七夕、腊八、除夕 |
| `m` / `dd` | 公历月日 | 双十一、愚人节、年末 |
| `quarter_end` | 是否季末 | 触发"忌季末冲业绩式上线" |

### 从命中到输出，中间有四道关

**第一道：去重。** 同一句话由多条规则给出时，只留权重最高的那条。

**第二道：仲裁。** 同一件事不能既「宜」又「忌」。两条规则各自命中时会撞车 ——
周四说"宜上线"，月末说"忌上线"。这里的规则是：

- **权重高的赢**；平手时**「忌」赢**（保守比激进划算）
- 判重不只看字面完全相同，**还算包含关系** —— 否则"宜上线"会躲过"忌季末冲业绩式上线"

**第三道：兜底。** 命中太少的日子（比如一个平平无奇的周二）从兜底池补到至少 4 条。
兜底池按日期取值，**同一条不会连着出现**。

**第四道：截断。** 各取前八条。

### 常年不变的三条，不占每日宜忌的位置

"密钥不进仓库""生产环境不是试验田""备份不用等出事"是**永远成立**的。
天天出现等于没有信息量，所以它们被抽出来（`ALWAYS`），固定放在输出底部一行，
不参与上面四道关，也不会占掉当天真正重要的条目。

### 条目长度上限

老黄历的宜忌是竖排短句，所以**每条不超过 9 个字**。
超过这个长度，既撑坏 HTML 版式，语气也散了。`tests/test_quality.py` 会拦住超长的条目。

### 权重怎么定的

权重不是拍的，是**按"犯了之后要还多少债"排的**。

比如"忌上线"在周五拿到 10 分，是所有条目里最高的。理由很实际：周五上线出事，你要赔上整个周末，而且没人会因此谢你。同理，"破日忌动生产环境"也是 10 分。

而兜底条目（"泡杯茶，空十分钟""换掉用久了的密码"）只有 1 分。它们有用，但今天不做也不会死人 —— 所以只在当天内容太少时才补上来。

### 为什么有些条目看起来在重复

比如周五既触发"收尾清理"，除日又触发"删代码、退订阅"。这不是 bug，是老黄历本来的样子 —— 从两个不同的体系同时指向一件事。工具会去重完全相同的文字，并拦下包含关系，但保留不同表述。

## 三、指数

四个指数（摸鱼、上线、谈加薪、早睡）由星期和建星加权算出，取值 0–100。

它们的作用不是精确测量，是给你一个**一眼就懂的量级**：周一摸鱼指数 20，周六 85，不需要解释。

---

## 四、这个工具不做什么

- **不做预测。** 指数不是概率，宜忌不是运势。
- **不替代判断。** "忌上线"的意思是"今天上线你要多留个心眼"，不是"不许上线"。
- **不算命。** 干支、建除是历法，不是命理。这个工具到历法为止。
